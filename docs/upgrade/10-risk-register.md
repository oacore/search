# 10 — Risk register

**Purpose:** every way the upgrade can break the app (R-001..R-091): rating, symptom, location, trigger, effect, step, mitigation.
**Read it** before a step (filter "Bites in") and when triaging a red test or prod incident.
**Owns** risk definitions and ratings. Elsewhere: tests per risk ([41](41-test-inventory.md) §3), status ([STATUS](STATUS.md), default OPEN), change sites ([20](20-change-sites.md), [60](60-design-ownership.md), [70](70-phase6.md), [80](80-phase7-antd.md)), quirks ([30](30-quirks-register.md)).

## 1. How to read

- **Sev** (impact), **Lik**: C/H/M/L. "(certain)" = reproduced on a real build.
- **Shows as:** SILENT = green build, no error; only a visual, SEO, network, analytics or data difference. LOUD = install/build/start failure or server-log error. LOUD-browser = browser console only. Process = breaks the plan's workflow. Security = exposure, no functional symptom.
- **Bites in:** step IDs from [50](50-roadmap.md); "—" = not scheduled.
- **Mitigation:** CS, OD ([90](90-open-decisions.md)), Q/S, D ([00](00-decisions.md)), OC, VG/RG ([55](55-gates-and-confidence.md)). Seeded-fault scope: 55 C1.
- **Evidence:** `path:line` at tree `a825839`; design paths in `../design`; `Xnn.n` = `review:00 Xnn.n` (`findings/review-2026-10-19/00-verified-findings.md`).
- **Order:** severity, then ID. IDs are never renumbered or reused; a re-rated row moves section and says "was …"; R-068..R-091 added 2026-10-20.
